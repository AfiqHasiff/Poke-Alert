## Overview

### Goal
Upgrade PokéAlert from v2.0.0 to v3.0.0, implementing an internal Baritone-based Anti-AFK movement system with comprehensive coordinate monitoring, teleport detection, and player safety features.

### Key Paradigm Shift
| v2.0.0 | v3.0.0 |
|--------|--------|
| Toggles external Anti-AFK keybind | Internal Anti-AFK via Baritone `#goto x z` commands |
| Passive Anti-AFK (external handles movement) | Active Anti-AFK (we control movement within defined region) |
| No coordinate tracking during Anti-AFK | Continuous coordinate monitoring with teleport detection |
| No moderator detection | Server player list & nearby player detection |
| External keybind mode | **REMOVED** - Only internal Baritone mode |

### Breaking Changes from v2.0.0
- ❌ External Anti-AFK keybind functionality **REMOVED**
- ❌ `antiAfkKeybind` config field **REMOVED**
- ❌ `AntiAfkManager.toggleAntiAfk()` keybind simulation **REMOVED**
- ✅ Replaced with Baritone-based internal movement system

## v3.0.0 Requirements Analysis

### Core Requirements

#### 1. Baritone Integration (Step 5 Replacement)
- Use Baritone's `#goto x z` command (Y handled automatically by Baritone)
- Define movement region with two X,Z coordinates: (X1,Z1) to (X2,Z2)
- **Initial Queue**: Generate 5 random locations within region
- **Perpetual Movement**: When at location 4 (second-to-last), add 3 more locations to queue
- **Result**: Continuous movement until safety stop or toggle off

#### 2. Coordinate Checker Task
- **Purpose**: Continuously monitor player position during Step 5
- **Arrival Detection**: Player is within `arrivalThreshold` blocks of destination (default: 3, configurable)
- **Teleport Detection**: Position change > `teleportDetectionOffset` blocks (default: 10, configurable)
- **Run Condition**: Only in overworld, only when Step 5 is active
- **Check Intervals**: Configurable via ModMenu/config (see Timing Configuration)

#### 3. Teleport/Manual Movement Detection
- **Mechanism**: Track incremental position changes during pathfinding
- **Example**: If at XK,ZK heading to X4,Z4, and position suddenly becomes XK+10,ZK+10, trigger stop
- **Threshold**: Configurable via `teleportDetectionOffset` (default: 10 blocks)
- **Action**: Cancel Anti-AFK, send Baritone `#stop`, notify user via **in-game chat only** (not Telegram)

#### 4. Step 5 Trigger Condition (Completion)
- **Requirement**: 3 successful location visits required to trigger Step 5 (Completion)
- **Confirmation**: Player position within `arrivalThreshold` blocks of each destination
- **Perpetual Mode**: After Step 5, queue continues with remaining locations + auto-replenishment
- **Note**: Step 5 is a checkpoint, not termination - Anti-AFK continues until stopped

#### 5. Timeout Handling
- **Per-Location Timeout**: Configurable (default: 45 seconds based on typical walk times)
- **On Timeout**: Skip to next location, notify via **in-game chat only** (not Telegram)
- **Consecutive Failures**: After 3 consecutive timeouts, trigger safety stop

#### 6. Player List Monitoring (Safety Feature)
- Check if configured usernames are on server
- Stop Anti-AFK and notify if detected

#### 7. Nearby Player Detection (Safety Feature)
- Detect configured players within proximity
- Stop Anti-AFK and notify if detected

### Safety Requirements
- Realm checker and coordinate checker must run continuously in background
- Not interrupted by Anti-AFK movement process
- Cancel all Baritone movement on safety trigger or toggle off (via `#stop` command)

### Perpetual Anti-AFK Flow (Step 4)

## Design Decisions

### Confirmed Decisions

| Decision | Resolution |
|----------|------------|
| Baritone Integration | Chat commands (`#goto x z`, `#stop`) - NOT API |
| Y Coordinate | Baritone handles Y automatically via `#goto x z` syntax |
| Arrival Threshold | 3 blocks default, configurable via ModMenu/config |
| Teleport Detection | 10 blocks default, configurable via ModMenu/config |
| Manual Movement | Triggers stop if > `teleportDetectionOffset` blocks |
| External Keybind Mode | **REMOVED** - v2.0.0 functionality deleted |
| Step 5 Trigger | 3 successful location visits required (was Step 6 in v2.0.0) |
| Queue Model | **Perpetual** - 5 initial, +3 when at second-to-last |
| Post-Step 5 | Anti-AFK continues (Step 5 is checkpoint, not termination) |
| Location Timeout | 45s default, notify **in-game only** (not Telegram) |
| Timing Intervals | **All configurable** via ModMenu/config |
| Queue Regeneration | Same region, new random locations (not reset on Step 5) |

### Baritone Command Syntax
```java
// Navigate to X, Z (Baritone determines Y automatically)
client.player.networkHandler.sendChatCommand("goto 100 200");  // X=100, Z=200

// Stop all Baritone processes
client.player.networkHandler.sendChatCommand("stop");
```

**Note**: Baritone commands use `sendChatCommand()` without the `#` prefix (Minecraft strips leading `/` and Baritone recognizes the command).

### Teleport Detection Algorithm
```
During pathfinding from current position (Xc, Zc) to destination (Xd, Zd):

Every coordinateCheckInterval ms (configurable, default 500ms):
  1. Get new position (Xn, Zn)
  2. Calculate delta: ΔX = |Xn - Xc|, ΔZ = |Zn - Zc|
  3. Calculate max delta: maxDelta = max(ΔX, ΔZ)
  4. If maxDelta > teleportDetectionOffset:
       → TELEPORT DETECTED → Stop Anti-AFK
  5. Update: Xc = Xn, Zc = Zn

Arrival Check:
  - Distance to destination = sqrt((Xn-Xd)² + (Zn-Zd)²)
  - If distance ≤ arrivalThreshold → ARRIVED
```

### Timing Configuration (v2.0.0 → v3.0.0)

**v2.0.0 Intervals (for reference):**
| Interval | Value | Purpose |
|----------|-------|---------|
| `CHECK_INTERVAL_SPAWN` | 200ms | Anti-AFK state check at spawn |
| `CHECK_INTERVAL_OVERWORLD` | 30000ms (30s) | Anti-AFK state check in overworld |
| `MOVEMENT_CHECK_INTERVAL` | 1000ms | Movement detection sampling |
| `Safety Monitor` | 3000ms (3s) | State mismatch detection |

**v3.0.0 Timing (NEW - All Configurable):**
| Interval | Default | Purpose | Configurable |
|----------|---------|---------|--------------|
| `coordinateCheckInterval` | 500ms | Position/teleport check during movement | ✅ ModMenu/config |
| `realmCheckIntervalSpawn` | 200ms | Realm state check at spawn | ✅ ModMenu/config |
| `realmCheckIntervalOverworld` | 30000ms | Realm state check in overworld | ✅ ModMenu/config |
| `playerMonitorInterval` | 5000ms | Player list/nearby check | ✅ ModMenu/config |
| `locationTimeout` | 45000ms (45s) | Max time per Baritone destination | ✅ ModMenu/config |

**Timeout vs State Check Conflict Resolution:**
- v2.0.0 checked if external Anti-AFK was running (movement detection)
- v3.0.0: WE are the Anti-AFK system, no external state to check
- `locationTimeout` (45s) is safe because:
  - We know Baritone is running (we sent the command)
  - Timeout means pathfinding issue, not Anti-AFK failure
  - Realm checker runs independently and won't false-alarm

## Architecture Changes

### State Machine for Step 4: Anti-AFK Start (Perpetual)

```
[IDLE]
   ↓ (Step 4 triggered after realm change)
[GENERATING_QUEUE]
   ↓ (generate 5 random locations in region)
[TRAVELING_TO_LOCATION_N]
   ↓ (send #goto x z)
[MONITORING_TRAVEL]
   ├─→ [TELEPORT_DETECTED] → [SAFETY_STOP] → Notify (in-game + Telegram) + End
   ├─→ [TIMEOUT] → Skip location, increment timeoutCount
   │      ├─→ (timeoutCount >= 3) → [SAFETY_STOP]
   │      └─→ (timeoutCount < 3) → [TRAVELING_TO_LOCATION_N+1]
   │
   └─→ [ARRIVED]
          ↓ (increment visitedCount, reset timeoutCount)
          ├─→ (visitedCount == 3 && !step5Done) → [STEP_5_COMPLETION] → continue
          ├─→ (currentIndex == queueSize - 2) → Add 3 more locations to queue
          └─→ [TRAVELING_TO_LOCATION_N+1]

[STEP_5_COMPLETION]
   ↓ (mark step5Done = true, send success notification via chat + Telegram)
   ↓ (Anti-AFK continues - NOT termination)
[TRAVELING_TO_LOCATION_N+1]
   ... (perpetual loop until safety stop or toggle off)

[SAFETY_STOP]
   ↓ (send #stop, notify in-game + Telegram)
[END]
```

### Queue Replenishment Logic
```
Initial state:
  Queue: [L1, L2, L3, L4, L5]  (5 locations)
  currentIndex = 0

After visiting L1, L2, L3:
  visitedCount = 3 → Trigger Step 5 completion
  Queue: [L1, L2, L3, L4, L5]
  currentIndex = 3 (pointing to L4)

When arriving at L4 (currentIndex == queueSize - 2):
  → Add 3 more locations: [L6, L7, L8]
  Queue: [L1, L2, L3, L4, L5, L6, L7, L8]
  currentIndex = 4 (now pointing to L5)

When arriving at L7 (currentIndex == queueSize - 2 again):
  → Add 3 more locations: [L9, L10, L11]
  Queue: [L1, L2, L3, L4, L5, L6, L7, L8, L9, L10, L11]
  ... continues perpetually
```

```java
public class BaritoneController {
    private static final MinecraftClient client = MinecraftClient.getInstance();
    private static final ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor();
    private static boolean isPathing = false;
    
    /**
     * Send goto command to navigate to X, Z (Y handled by Baritone)
     * Always sends #stop first to clear any existing path
     * @param x Target X coordinate
     * @param z Target Z coordinate
     */
    public static void gotoLocation(int x, int z) {
        stop();  // Clear any existing path first
        scheduler.schedule(() -> {
            if (client.player != null) {
                client.player.networkHandler.sendChatCommand("goto " + x + " " + z);
                isPathing = true;
                PokeAlertClient.LOGGER.info("Baritone: Navigating to X=" + x + ", Z=" + z);
            }
        }, 100, TimeUnit.MILLISECONDS);  // Small delay after stop
    }
    
    /**
     * Stop all Baritone processes immediately
     */
    public static void stop() {
        if (client.player != null) {
            client.player.networkHandler.sendChatCommand("stop");
            isPathing = false;
            PokeAlertClient.LOGGER.info("Baritone: Stopped");
        }
    }
    
    /**
     * Check if Baritone is currently pathing (based on our tracking)
     * Note: This tracks OUR commands, not actual Baritone state
     * @return true if we've sent a goto and haven't stopped
     */
    public static boolean isPathing() {
        return isPathing;
    }
    
    /**
     * Mark pathing as complete (called when arrival detected)
     */
    public static void markPathComplete() {
        isPathing = false;
    }
    
    /**
     * Shutdown the scheduler (call on mod unload)
     */
    public static void shutdown() {
        scheduler.shutdown();
    }
}
```

#### 2. `CoordinateMonitor.java` (New)
```java
public class CoordinateMonitor {
    private static final MinecraftClient client = MinecraftClient.getInstance();
    private static ScheduledExecutorService scheduler;
    private static ScheduledFuture<?> monitorTask;
    
    // Configuration (set from PokeAlertConfig)
    private static int arrivalThreshold = 3;
    private static int teleportDetectionOffset = 10;
    private static int checkIntervalMs = 500;
    
    // State tracking
    private static int destinationX, destinationZ;
    private static int lastX, lastZ;
    private static String currentWorld;
    private static boolean isMonitoring = false;
    
    // Callbacks
    private static Runnable onTeleportCallback;
    private static Runnable onArrivalCallback;
    private static Consumer<String> onWorldChangeCallback;
    
    /**
     * Start monitoring with specified configuration
     * @param config PokeAlertConfig to read thresholds from
     */
    public static void startMonitoring(PokeAlertConfig config) {
        arrivalThreshold = config.arrivalThreshold;
        teleportDetectionOffset = config.teleportDetectionOffset;
        checkIntervalMs = config.coordinateCheckInterval;
        
        if (scheduler == null) {
            scheduler = Executors.newSingleThreadScheduledExecutor();
        }
        
        // Initialize position
        if (client.player != null) {
            lastX = (int) client.player.getX();
            lastZ = (int) client.player.getZ();
            currentWorld = client.world.getRegistryKey().getValue().toString();
        }
        
        isMonitoring = true;
        scheduleMonitorTask();
        PokeAlertClient.LOGGER.info("CoordinateMonitor: Started with arrival=" + 
            arrivalThreshold + ", teleport=" + teleportDetectionOffset);
    }
    
    /**
     * Stop all monitoring
     */
    public static void stopMonitoring() {
        isMonitoring = false;
        if (monitorTask != null) {
            monitorTask.cancel(false);
            monitorTask = null;
        }
        PokeAlertClient.LOGGER.info("CoordinateMonitor: Stopped");
    }
    
    /**
     * Set current destination for arrival checking
     * @param x Destination X coordinate
     * @param z Destination Z coordinate
     */
    public static void setDestination(int x, int z) {
        destinationX = x;
        destinationZ = z;
        // Reset last position to current to avoid false teleport detection
        if (client.player != null) {
            lastX = (int) client.player.getX();
            lastZ = (int) client.player.getZ();
        }
        PokeAlertClient.LOGGER.info("CoordinateMonitor: Destination set to X=" + x + ", Z=" + z);
    }
    
    /**
     * Check if player has arrived at current destination
     * Uses 2D distance (X, Z only)
     * @return true if within arrivalThreshold blocks of destination
     */
    public static boolean hasArrived() {
        if (client.player == null) return false;
        
        int currentX = (int) client.player.getX();
        int currentZ = (int) client.player.getZ();
        
        double distance = Math.sqrt(
            Math.pow(currentX - destinationX, 2) + 
            Math.pow(currentZ - destinationZ, 2)
        );
        
        return distance <= arrivalThreshold;
    }
    
    /**
     * Check for teleport or manual movement exceeding threshold
     * Compares current position to last checked position
     * @return true if position delta > teleportDetectionOffset
     */
    public static boolean checkForTeleport() {
        if (client.player == null) return false;
        
        int currentX = (int) client.player.getX();
        int currentZ = (int) client.player.getZ();
        
        int deltaX = Math.abs(currentX - lastX);
        int deltaZ = Math.abs(currentZ - lastZ);
        int maxDelta = Math.max(deltaX, deltaZ);
        
        return maxDelta > teleportDetectionOffset;
    }
    
    /**
     * Get current player position
     * @return int[] with [x, z] or null if player unavailable
     */
    public static int[] getCurrentPosition() {
        if (client.player == null) return null;
        return new int[] { (int) client.player.getX(), (int) client.player.getZ() };
    }
    
    /**
     * Register callback for teleport detection events
     * @param callback Runnable to execute when teleport detected
     */
    public static void onTeleportDetected(Runnable callback) {
        onTeleportCallback = callback;
    }
    
    /**
     * Register callback for arrival events
     * @param callback Runnable to execute when arrived at destination
     */
    public static void onArrival(Runnable callback) {
        onArrivalCallback = callback;
    }
    
    /**
     * Register callback for world change events
     * @param callback Consumer receiving the new world name
     */
    public static void onWorldChange(Consumer<String> callback) {
        onWorldChangeCallback = callback;
    }
    
    /**
     * Internal: Schedule the monitoring task
     */
    private static void scheduleMonitorTask() {
        monitorTask = scheduler.scheduleAtFixedRate(() -> {
            if (!isMonitoring || client.player == null || client.world == null) return;
            
            try {
                // Check for world change first
                String newWorld = client.world.getRegistryKey().getValue().toString();
                if (!newWorld.equals(currentWorld)) {
                    PokeAlertClient.LOGGER.warn("CoordinateMonitor: World changed from " + 
                        currentWorld + " to " + newWorld);
                    if (onWorldChangeCallback != null) {
                        onWorldChangeCallback.accept(newWorld);
                    }
                    currentWorld = newWorld;
                    return;  // Skip other checks this tick
                }
                
                // Check arrival BEFORE teleport (arrival takes priority)
                if (hasArrived()) {
                    PokeAlertClient.LOGGER.info("CoordinateMonitor: Arrived at destination");
                    if (onArrivalCallback != null) {
                        onArrivalCallback.run();
                    }
                    // Update last position after arrival
                    lastX = (int) client.player.getX();
                    lastZ = (int) client.player.getZ();
                    return;
                }
                
                // Check for teleport
                if (checkForTeleport()) {
                    int currentX = (int) client.player.getX();
                    int currentZ = (int) client.player.getZ();
                    PokeAlertClient.LOGGER.warn("CoordinateMonitor: Teleport detected! " +
                        "Last: (" + lastX + "," + lastZ + ") → Current: (" + currentX + "," + currentZ + ")");
                    if (onTeleportCallback != null) {
                        onTeleportCallback.run();
                    }
                    return;
                }
                
                // Update last position for next check
                lastX = (int) client.player.getX();
                lastZ = (int) client.player.getZ();
                
            } catch (Exception e) {
                PokeAlertClient.LOGGER.error("CoordinateMonitor: Error in monitor task", e);
            }
        }, 0, checkIntervalMs, TimeUnit.MILLISECONDS);
    }
    
    /**
     * Shutdown the scheduler (call on mod unload)
     */
    public static void shutdown() {
        stopMonitoring();
        if (scheduler != null) {
            scheduler.shutdown();
        }
    }
}
```

#### 3. `PlayerMonitor.java` (New)
```java
public class PlayerMonitor {
    private static final MinecraftClient client = MinecraftClient.getInstance();
    private static ScheduledExecutorService scheduler;
    private static ScheduledFuture<?> monitorTask;
    
    // Configuration
    private static List<String> playersToAvoid = new ArrayList<>();
    private static double nearbyDetectionRadius = 32.0;
    private static int checkIntervalMs = 5000;
    private static boolean enablePlayerList = true;
    private static boolean enableNearbyDetection = true;
    
    // State
    private static boolean isMonitoring = false;
    
    // Callbacks
    private static Consumer<String> onPlayerDetectedCallback;
    private static BiConsumer<String, String> onPlayerDetectedWithTypeCallback;  // (playerName, detectionType)
    
    /**
     * Start continuous player monitoring
     * @param config PokeAlertConfig to read settings from
     */
    public static void startMonitoring(PokeAlertConfig config) {
        playersToAvoid = Arrays.asList(config.playersToAvoid).stream()
            .map(String::toLowerCase)
            .collect(Collectors.toList());
        nearbyDetectionRadius = config.nearbyPlayerDetectionRadius;
        checkIntervalMs = config.playerMonitorInterval;
        enablePlayerList = config.enablePlayerListMonitoring;
        enableNearbyDetection = config.enableNearbyPlayerDetection;
        
        if (playersToAvoid.isEmpty()) {
            PokeAlertClient.LOGGER.info("PlayerMonitor: No players to avoid configured, skipping");
            return;
        }
        
        if (scheduler == null) {
            scheduler = Executors.newSingleThreadScheduledExecutor();
        }
        
        isMonitoring = true;
        scheduleMonitorTask();
        PokeAlertClient.LOGGER.info("PlayerMonitor: Started monitoring for " + 
            playersToAvoid.size() + " players, radius=" + nearbyDetectionRadius);
    }
    
    /**
     * Stop all monitoring
     */
    public static void stopMonitoring() {
        isMonitoring = false;
        if (monitorTask != null) {
            monitorTask.cancel(false);
            monitorTask = null;
        }
        PokeAlertClient.LOGGER.info("PlayerMonitor: Stopped");
    }
    
    /**
     * Check server player list for avoided players
     * @return List of detected player names (empty if none found)
     */
    public static List<String> checkPlayerList() {
        List<String> detected = new ArrayList<>();
        
        if (client.getNetworkHandler() == null) return detected;
        
        Collection<PlayerListEntry> playerList = client.getNetworkHandler().getPlayerList();
        for (PlayerListEntry entry : playerList) {
            String playerName = entry.getProfile().getName().toLowerCase();
            if (playersToAvoid.contains(playerName)) {
                detected.add(entry.getProfile().getName());  // Return original case
            }
        }
        
        return detected;
    }
    
    /**
     * Check for nearby avoided players within detection radius
     * @return List of detected player names (empty if none found)
     */
    public static List<String> checkNearbyPlayers() {
        List<String> detected = new ArrayList<>();
        
        if (client.world == null || client.player == null) return detected;
        
        for (PlayerEntity player : client.world.getPlayers()) {
            // Skip self
            if (player == client.player) continue;
            
            String playerName = player.getName().getString().toLowerCase();
            if (playersToAvoid.contains(playerName)) {
                double distance = player.distanceTo(client.player);
                if (distance <= nearbyDetectionRadius) {
                    detected.add(player.getName().getString());  // Return original case
                    PokeAlertClient.LOGGER.warn("PlayerMonitor: Detected " + 
                        player.getName().getString() + " at distance " + 
                        String.format("%.1f", distance) + " blocks");
                }
            }
        }
        
        return detected;
    }
    
    /**
     * Register callback for player detection events
     * @param callback Consumer receiving the detected player name
     */
    public static void onPlayerDetected(Consumer<String> callback) {
        onPlayerDetectedCallback = callback;
    }
    
    /**
     * Register callback with detection type information
     * @param callback BiConsumer receiving (playerName, detectionType)
     *                 where detectionType is "playerlist" or "nearby"
     */
    public static void onPlayerDetectedWithType(BiConsumer<String, String> callback) {
        onPlayerDetectedWithTypeCallback = callback;
    }
    
    /**
     * Update the list of players to avoid (runtime update)
     * @param players Array of player names
     */
    public static void updatePlayersToAvoid(String[] players) {
        playersToAvoid = Arrays.asList(players).stream()
            .map(String::toLowerCase)
            .collect(Collectors.toList());
        PokeAlertClient.LOGGER.info("PlayerMonitor: Updated avoid list, now " + 
            playersToAvoid.size() + " players");
    }
    
    /**
     * Internal: Schedule the monitoring task
     */
    private static void scheduleMonitorTask() {
        monitorTask = scheduler.scheduleAtFixedRate(() -> {
            if (!isMonitoring) return;
            
            try {
                // Check player list
                if (enablePlayerList) {
                    List<String> listDetected = checkPlayerList();
                    for (String player : listDetected) {
                        PokeAlertClient.LOGGER.warn("PlayerMonitor: " + player + 
                            " detected in server player list!");
                        triggerCallback(player, "playerlist");
                    }
                }
                
                // Check nearby players
                if (enableNearbyDetection) {
                    List<String> nearbyDetected = checkNearbyPlayers();
                    for (String player : nearbyDetected) {
                        PokeAlertClient.LOGGER.warn("PlayerMonitor: " + player + 
                            " detected nearby!");
                        triggerCallback(player, "nearby");
                    }
                }
                
            } catch (Exception e) {
                PokeAlertClient.LOGGER.error("PlayerMonitor: Error in monitor task", e);
            }
        }, 0, checkIntervalMs, TimeUnit.MILLISECONDS);
    }
    
    /**
     * Internal: Trigger appropriate callbacks
     */
    private static void triggerCallback(String playerName, String detectionType) {
        if (onPlayerDetectedCallback != null) {
            onPlayerDetectedCallback.accept(playerName);
        }
        if (onPlayerDetectedWithTypeCallback != null) {
            onPlayerDetectedWithTypeCallback.accept(playerName, detectionType);
        }
    }
    
    /**
     * Shutdown the scheduler (call on mod unload)
     */
    public static void shutdown() {
        stopMonitoring();
        if (scheduler != null) {
            scheduler.shutdown();
        }
    }
```

```java
public class SafetyManager {
    private static final AtomicBoolean safetyLock = new AtomicBoolean(false);
    private static volatile String lastSafetyReason = null;
    private static volatile long lastSafetyTime = 0;
    
    // Callbacks
    private static Consumer<String> onSafetyStopCallback;
    
    // Safety reasons (constants for consistency)
    public static final String REASON_TELEPORT = "Teleport/Manual movement detected";
    public static final String REASON_PLAYER_LIST = "Avoided player detected in server";
    public static final String REASON_PLAYER_NEARBY = "Avoided player detected nearby";
    public static final String REASON_WORLD_CHANGE = "Unexpected world change";
    public static final String REASON_TIMEOUT = "Too many consecutive timeouts";
    public static final String REASON_USER_TOGGLE = "User toggled off";
    public static final String REASON_DISCONNECT = "Player disconnected";
    
    /**
     * Attempt to trigger safety stop (thread-safe, first caller wins)
     * Stops all monitors and Baritone, sends notifications
     * 
     * @param reason Description of why safety was triggered (use REASON_* constants)
     * @param notifyTelegram Whether to send Telegram notification
     * @return true if this call triggered the stop, false if already stopped
     */
    public static boolean triggerSafetyStop(String reason, boolean notifyTelegram) {
        // Atomic check-and-set - only first caller succeeds
        if (safetyLock.compareAndSet(false, true)) {
            lastSafetyReason = reason;
            lastSafetyTime = System.currentTimeMillis();
            
            PokeAlertClient.LOGGER.error("SafetyManager: SAFETY STOP - " + reason);
            
            // Stop all systems
            BaritoneController.stop();
            CoordinateMonitor.stopMonitoring();
            PlayerMonitor.stopMonitoring();
            
            // Send in-game notification (always)
            sendInGameNotification(reason);
            
            // Send Telegram notification (if requested)
            if (notifyTelegram) {
                sendTelegramNotification(reason);
            }
            
            // Trigger callback
            if (onSafetyStopCallback != null) {
                onSafetyStopCallback.accept(reason);
            }
            
            return true;
        }
        
        // Already stopped - log but don't duplicate notifications
        PokeAlertClient.LOGGER.info("SafetyManager: Ignoring duplicate safety stop - " + reason);
        return false;
    }
    
    /**
     * Check if safety has been triggered
     * @return true if safety stop is currently active
     */
    public static boolean isSafetyTriggered() {
        return safetyLock.get();
    }
    
    /**
     * Get the reason for last safety stop
     * @return Reason string, or null if no safety stop has occurred
     */
    public static String getLastSafetyReason() {
        return lastSafetyReason;
    }
    
    /**
     * Get timestamp of last safety stop
     * @return Unix timestamp in milliseconds, or 0 if never triggered
     */
    public static long getLastSafetyTime() {
        return lastSafetyTime;
    }
    
    /**
     * Reset safety state (called when starting new automation cycle)
     * Must be called before starting Step 4 (Anti-AFK)
     */
    public static void reset() {
        safetyLock.set(false);
        // Don't clear lastSafetyReason - useful for debugging
        PokeAlertClient.LOGGER.info("SafetyManager: Reset for new cycle");
    }
    
    /**
     * Register callback for safety stop events
     * @param callback Consumer receiving the safety reason
     */
    public static void onSafetyStop(Consumer<String> callback) {
        onSafetyStopCallback = callback;
    }
    
    /**
     * Internal: Send in-game chat notification
     */
    private static void sendInGameNotification(String reason) {
        MinecraftClient client = MinecraftClient.getInstance();
        if (client.player != null) {
            PokeAlertConfig config = PokeAlertClient.getInstance().config;
            if (config.inGameTextEnabled) {
                client.execute(() -> {
                    Text message = Text.literal("[")
                        .formatted(Formatting.GRAY)
                        .append(Text.literal("PokeAlert").formatted(Formatting.RED))
                        .append(Text.literal("] ").formatted(Formatting.GRAY))
                        .append(Text.literal("⚠️ SAFETY STOP: ").formatted(Formatting.RED, Formatting.BOLD))
                        .append(Text.literal(reason).formatted(Formatting.YELLOW));
                    client.player.sendMessage(message, false);
                });
            }
        }
    }

        if (config.telegramEnabled && config.isTelegramValid()) {

                message.append("• <b>Reason:</b> <i>").append(reason).append("</i>\n");
                message.append("• <b>Time:</b> <code>")

                    .append("</code>\n");
                message.append("• <b>Action:</b> Anti-AFK stopped, requires manual restart");
                
                telegram.sendEggTimerNotification(message.toString());
```

```java
public class LocationQueue {
    private List<int[]> locations = new ArrayList<>();  // List of [x, z] arrays
    private int currentIndex = 0;
    private int visitedCount = 0;
    private int consecutiveTimeouts = 0;
    private boolean step5Completed = false;  // Step 5 in v3.0.0 (was Step 6)
    private AntiAfkRegion region;  // Store for replenishment
    
    // Configuration (from PokeAlertConfig)
    private int initialQueueSize = 5;
    private int replenishCount = 3;
    private int locationsForStep5 = 3;
    private int maxConsecutiveTimeouts = 3;
    
    /**
     * Initialize queue with random locations within region
     * @param region The Anti-AFK region to generate locations in
     * @param config Configuration for queue settings
     */
    public void initialize(AntiAfkRegion region, PokeAlertConfig config) {
        this.region = region;
        this.initialQueueSize = config.initialQueueSize;
        this.replenishCount = config.replenishCount;
        this.locationsForStep5 = config.locationsForStep6;  // Config still uses old name
        this.maxConsecutiveTimeouts = config.maxConsecutiveTimeouts;
        
        // Validate region
        if (!region.hasValidArea()) {
            PokeAlertClient.LOGGER.error("LocationQueue: Region has no valid area!");
            return;
        }
        
        // Reset state
        reset();
        
        // Generate initial locations
        for (int i = 0; i < initialQueueSize; i++) {
            locations.add(region.getRandomPosition());
        }
        
        PokeAlertClient.LOGGER.info("LocationQueue: Initialized with " + locations.size() + 
            " locations in region (" + region.x1 + "," + region.z1 + ") to (" + 
            region.x2 + "," + region.z2 + ")");
    }
    
    /**
     * Get current destination coordinates
     * @return int[] with [x, z] or null if queue empty
     */
    public int[] getCurrentDestination() {
        if (currentIndex >= locations.size()) {
            return null;
        }
        return locations.get(currentIndex);
    }
    
    /**
     * Mark current location as visited and advance to next
     * Handles queue replenishment when at second-to-last location
     */
    public void markVisitedAndAdvance() {
        visitedCount++;
        consecutiveTimeouts = 0;  // Reset timeout counter on success
        
        PokeAlertClient.LOGGER.info("LocationQueue: Visited location " + (currentIndex + 1) + 
            ", total visited: " + visitedCount);
        
        // Check if we need to replenish (at second-to-last)
        if (needsReplenishment()) {
            replenish();
        }
        
        currentIndex++;
    }
    
    /**
     * Mark current location as timed out (skip) and advance
     * @return true if should continue, false if max consecutive timeouts reached
     */
    public boolean markTimeoutAndAdvance() {
        consecutiveTimeouts++;
        
        PokeAlertClient.LOGGER.warn("LocationQueue: Timeout at location " + (currentIndex + 1) + 
            ", consecutive timeouts: " + consecutiveTimeouts);
        
        if (consecutiveTimeouts >= maxConsecutiveTimeouts) {
            PokeAlertClient.LOGGER.error("LocationQueue: Max consecutive timeouts reached (" + 
                maxConsecutiveTimeouts + ")");
            return false;  // Signal to trigger safety stop
        }
        
        // Skip to next location
        currentIndex++;
        
        // Check if we need to replenish
        if (needsReplenishment()) {
            replenish();
        }
        
        return true;  // Continue
    }
    
    /**
     * Get number of successfully visited locations
     * @return Count of locations visited without timeout
     */
    public int getVisitedCount() {
        return visitedCount;
    }
    
    /**
     * Get current consecutive timeout count
     * @return Number of consecutive timeouts
     */
    public int getConsecutiveTimeouts() {
        return consecutiveTimeouts;
    }
    
    /**
     * Check if Step 5 (Completion) should trigger
     * @return true if visitedCount >= locationsForStep5 AND not yet triggered
     */
    public boolean shouldTriggerStep5() {
        return visitedCount >= locationsForStep5 && !step5Completed;
    }
    
    /**
     * Mark Step 5 as completed
     * Called after sending completion notification
     */
    public void markStep5Completed() {
        step5Completed = true;
        PokeAlertClient.LOGGER.info("LocationQueue: Step 5 marked complete, Anti-AFK continues");
    }
    
    /**
     * Check if Step 5 has been completed
     * @return true if completion has been triggered
     */
    public boolean isStep5Completed() {
        return step5Completed;
    }
    
    /**
     * Check if at second-to-last location (need to replenish)
     * @return true if currentIndex == locations.size() - 2
     */
    public boolean needsReplenishment() {
        return currentIndex >= locations.size() - 2;
    }
    
    /**
     * Add more random locations to queue
     * Called when at second-to-last location
     */
    public void replenish() {
        if (region == null || !region.hasValidArea()) {
            PokeAlertClient.LOGGER.error("LocationQueue: Cannot replenish - invalid region");
            return;
        }
        
        int oldSize = locations.size();
        for (int i = 0; i < replenishCount; i++) {
            locations.add(region.getRandomPosition());
        }
        
        PokeAlertClient.LOGGER.info("LocationQueue: Replenished " + replenishCount + 
            " locations, queue size: " + oldSize + " → " + locations.size());
    }
    
    /**
     * Reset queue state completely (for new cycle)
     * Call when starting fresh automation
     */
    public void reset() {
        locations.clear();
        currentIndex = 0;
        visitedCount = 0;
        consecutiveTimeouts = 0;
        step5Completed = false;
        PokeAlertClient.LOGGER.info("LocationQueue: Reset");
    }
    
    /**
     * Reset timeout counter only (called on successful arrival)
     */
    public void resetTimeoutCounter() {
        consecutiveTimeouts = 0;
    }
    
    /**
     * Get current queue size
     * @return Total locations in queue
     */
    public int getQueueSize() {
        return locations.size();
    }
    
    /**
     * Get current index in queue
     * @return Current position index
     */
    public int getCurrentIndex() {
        return currentIndex;
    }
    
    /**
     * Check if queue is empty or exhausted
     * @return true if no more locations
     */
    public boolean isEmpty() {
        return locations.isEmpty() || currentIndex >= locations.size();
    }
}
```

## Race Condition Analysis

### Identified Scenarios

#### Scenario 1: Multiple Safety Triggers
**Situation**: Teleport detection AND player detection trigger simultaneously
**Problem**: Both try to stop Anti-AFK and send notifications
**Solution**: 
```java
// Use AtomicBoolean flag
private static final AtomicBoolean safetyTriggered = new AtomicBoolean(false);

public void onSafetyEvent(String reason) {
    // Only first trigger wins
    if (safetyTriggered.compareAndSet(false, true)) {
        BaritoneController.stop();
        sendNotification(reason);
        // ... cleanup
    }
    // Subsequent triggers are ignored
}
```

#### Scenario 2: Arrival vs Teleport Detection Race
**Situation**: Player arrives at destination but position delta is large (due to Baritone pathing)
**Problem**: Could falsely trigger teleport detection when actually arrived
**Solution**: 
```java
// Check arrival BEFORE teleport detection
if (hasArrived()) {
    // Arrived successfully - no teleport check needed
    markVisitedAndAdvance();
} else if (checkForTeleport()) {
    // Not arrived + large delta = teleport
    triggerSafetyStop();
}
```

#### Scenario 3: Baritone Command Overlap
**Situation**: New `#goto` sent before previous completes
**Problem**: Baritone might get confused or queue commands
**Solution**: 
```java
// Always send #stop before new #goto
public static void gotoLocation(int x, int z) {
    stop();  // Clear any existing path
    // Small delay for safety
    scheduler.schedule(() -> {
        sendCommand("goto " + x + " " + z);
    }, 100, TimeUnit.MILLISECONDS);
}
```

#### Scenario 4: Config Change During Active Anti-AFK
**Situation**: User changes region or thresholds while Step 5 is running
**Problem**: Could cause inconsistent behavior
**Solution**:
- Option A: Ignore config changes until cycle completes
- Option B: Apply new config on next location
- **Recommendation**: Option B - apply on next location, log warning

#### Scenario 5: World Change During Step 5
**Situation**: Player teleported to different dimension during Anti-AFK
**Problem**: Coordinate monitor comparing wrong-world positions
**Solution**:
```java
// Track current world
private static String currentWorld;

public void checkPosition() {
    String newWorld = getWorldName();
    if (!newWorld.equals(currentWorld)) {
        // World changed - trigger safety stop
        triggerSafetyStop("World changed unexpectedly");
        return;
    }
    // ... normal position checks
}
```

#### Scenario 6: Disconnect During Step 5
**Situation**: Player disconnects while Anti-AFK is running
**Problem**: Monitors might still be running, reconnect state unclear
**Solution**:
- Stop all monitors on disconnect
- Reset state completely
- On reconnect, restart from Step 1 if at spawn

### Safety Flag Architecture
```java
public class SafetyManager {
    private static final AtomicBoolean safetyLock = new AtomicBoolean(false);
    private static String lastSafetyReason = null;
    
    /**
     * Attempt to trigger safety stop
     * @return true if this call triggered the stop, false if already stopped
     */
    public static boolean triggerSafetyStop(String reason) {
        if (safetyLock.compareAndSet(false, true)) {
            lastSafetyReason = reason;
            BaritoneController.stop();
            CoordinateMonitor.stopMonitoring();
            PlayerMonitor.stopMonitoring();
            // Send notifications
            return true;
        }
        return false;
    }
    
    /**
     * Reset safety state (called when starting new cycle)
     */
    public static void reset() {
        safetyLock.set(false);
        lastSafetyReason = null;
    }
}
```

## Potential Issues and Mitigations

### Issue 1: Memory Growth from Perpetual Queue
**Problem**: Queue grows indefinitely as locations are added but never removed.
**Impact**: Long-running sessions (hours) could accumulate thousands of entries.
**Mitigation**:
```java
// In LocationQueue.replenish():
// Trim old visited locations periodically
if (locations.size() > 50 && currentIndex > 20) {
    locations = locations.subList(currentIndex - 5, locations.size());
    currentIndex = 5;  // Keep some buffer
    PokeAlertClient.LOGGER.info("LocationQueue: Trimmed old locations");
}
```

### Issue 2: Small Region → Duplicate Locations
**Problem**: If region is very small (e.g., 5x5), random locations might repeat or be too close.
**Impact**: Player just walks back and forth to same spots.
**Mitigation**:
- Validate minimum region size (suggest 20x20 minimum)
- In `getRandomPosition()`, try to avoid generating location within `arrivalThreshold` of last N locations
- Show warning in config UI if region is too small

### Issue 3: Baritone Not Installed
**Problem**: User doesn't have Baritone mod installed, commands do nothing.
**Impact**: Anti-AFK appears to start but player never moves.
**Mitigation**:
- Add startup check: Send test command, look for Baritone response in chat
- If not detected, show warning and disable Egg Hatcher
- Add config option: `baritoneDetected` (auto-set, not user-editable)

### Issue 4: Unreachable Location Generated
**Problem**: Random location is in water, in a wall, or otherwise unreachable.
**Impact**: Baritone times out, consecutive timeout counter increases.
**Mitigation**:
- The timeout system handles this (skip after timeout)
- 3 consecutive timeouts triggers safety stop, which is appropriate
- Consider: Add config for "timeout recovery" - on timeout, generate new location instead of advancing

### Issue 5: Thread Safety - Concurrent State Access
**Problem**: Multiple schedulers (CoordinateMonitor, PlayerMonitor, EggHatcher) access shared state.
**Impact**: Race conditions, inconsistent state, double-triggers.
**Mitigation**:
- `SafetyManager` uses `AtomicBoolean` for lock
- All monitors use single-threaded schedulers
- State variables marked `volatile` where needed
- Clear ownership: Only `EggHatcher` manages high-level state

### Issue 6: Disconnect During Step 4
**Problem**: Player disconnects while Anti-AFK is running.
**Impact**: Monitors might still be running, reconnect behavior unclear.
**Mitigation**:
```java
// In PokeAlertClient disconnect handler:
ClientPlayConnectionEvents.DISCONNECT.register((handler, client) -> {
    SafetyManager.triggerSafetyStop(SafetyManager.REASON_DISCONNECT, false);
    LocationQueue.reset();
    // EggHatcher will restart from Step 1 on reconnect if at spawn
});
```

### Issue 7: Reconnect at Overworld (Not Spawn)
**Problem**: Player reconnects in overworld, should Anti-AFK resume?
**Impact**: Unclear state - was Anti-AFK running before disconnect?
**Mitigation**:
- On reconnect, DO NOT auto-resume Anti-AFK
- User must toggle Egg Hatcher again to restart
- Show message: "Egg Hatcher reset due to disconnect, toggle to restart"

### Issue 8: Config Change During Active Step 4
**Problem**: User changes region or thresholds via ModMenu while Anti-AFK is running.
**Impact**: Could cause unexpected behavior, old region vs new region.
**Mitigation**:
- Apply new config values on NEXT location (not current)
- Log warning when config changes during active automation
- Option: Block config changes during Step 4 (show "Stop Anti-AFK first" message)

### Issue 9: False Teleport Detection During Baritone Path
**Problem**: Baritone takes a large jump (falling, swimming up) that exceeds threshold.
**Impact**: False positive teleport detection.
**Mitigation**:
- Check arrival BEFORE teleport (already implemented)
- Consider: Track Y separately, only flag if X OR Z delta exceeds threshold (not combined)
- Consider: Increase threshold during active pathing (e.g., threshold * 1.5)

### Issue 10: Player List Shows Avoided Player Who Logged Off
**Problem**: Player list might cache old data briefly after player leaves.
**Impact**: False positive player detection.
**Mitigation**:
- Low impact - player list updates quickly
- Safety stop is appropriate even if brief detection
- Consider: Require 2 consecutive detections before triggering (debounce)

### Issue 11: World Change Detection vs Teleport Detection
**Problem**: `/spawn` command changes world, could trigger both world change AND teleport.
**Impact**: Duplicate safety triggers, multiple notifications.
**Mitigation**:
- `SafetyManager.safetyLock` ensures only first trigger executes
- Check world change BEFORE teleport detection in `CoordinateMonitor`
- World change has higher priority and stops further checks

### Issue 12: Arrival Threshold vs Teleport Threshold Conflict
**Problem**: If `arrivalThreshold` (3) is close to `teleportDetectionOffset` (10), edge cases may occur.
**Impact**: Arriving at location with 8-block jump might trigger teleport.
**Mitigation**:
- Config validation: Ensure `teleportDetectionOffset` >= `arrivalThreshold` * 2
- Check arrival BEFORE teleport (already implemented)
- Consider: Suspend teleport detection for 1 check after setting new destination

### Issue 13: Baritone Command Timing
**Problem**: Sending `#goto` immediately after `#stop` might be ignored.
**Impact**: Player doesn't move to next location.
**Mitigation**:
- `BaritoneController.gotoLocation()` has 100ms delay after stop
- Consider: Increase to 200ms if issues observed
- Add retry logic if position unchanged after 5 seconds

### Issue 14: Long Queue Causing UI/Log Spam
**Problem**: Queue grows large, logging every location clutters console.
**Impact**: Performance impact from excessive logging, hard to debug.
**Mitigation**:
- Reduce logging verbosity after Step 5 completion
- Log queue size periodically (every 10 locations) instead of every addition
- Only log detailed info at DEBUG level
