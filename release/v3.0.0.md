Our goal is to revamp by going into version 3.0.0. The new version will include new built triggers for anti-afk for Egg Hatcher process.
Currently in version 2.0.0, we are toggling a specific keybind which is tied to an external anti-afk program which handles the anti-afk process by moving the player. However, in the newer version, we will be also handling the anti-afk process internally paired with a program called baritone. We will be using baritone's #goto command to move player in a specific region which we will define in the config or via modmenu for overworld egg hatching process. We will also experiment on adding security layers to prevent us from getting caught by server moderators from detecting our anti-afk process.

Below are requirements for the new version:
1. Step 1 until step 4 of Egg Hatcher will be the same as version 2.0.0.
2. Step 5 will be using baritone's #goto command to move player in a specific region which we will define in the config or via modmenu for overworld egg hatching process. The idea is that in the config, we would be setting two coordinates in the overworld, this will be the region where our anti-afk process will be playing out. Lets say the defined region is from X1 Y1 Z1 to X2 Y2 Z2, our process will randomly decide where to travel to within the region and queue at least 5 locations to travel to within the region before regenerating a new set of random locations within the region.
3. Step 5 will also take into account of player's current coordinate at all times for safety purposes. This is for cases for when anti-afk is enabled an a moderator teleports us to a different coordinate which we can detect by having an offset of around 10 blocks from the players current position. For example, if we are at X1 Y1 Z1, and the player is teleported to X1 Y1 Z2 if the difference between Z2 and Z1 is more than 10 blocks, we can detect that the player has been teleported and we can cancel the anti-afk process and notify the user via in-game chat message and telegram.
4. Step 6 will only be triggered if there are 3 succesful locations travelled within the region defined in the config or via modmenu.
5. Realm checker and anti-afk state checker must be constantly running in the background and not be affected by the anti-afk process. These two are critical for the safety of the process and must not be interrupted.
6. Safety-checker must be able to detect if the player has been teleported to a different coordinate and cancel the anti-afk process and notify the user via in-game chat message and telegram by utilizing realm checker and ant-afk state checker.
7. Any locations queued and existing traveling process via baritone must be cancelled (using baritone's #stop command) if the player has been teleported to a different coordinate or if Egg Hatcher is toggled off .Notify the user via in-game chat message and telegram.
8. Step 5 will no longer work like v2.0.0 where it will be toggling the anti-afk keybind to move the player. Instead, it will be using baritone's #goto command to move the player to the next location in the queue.
9. Introduce a new coordinate checker task that persists when Step 5 is triggered and runs in the background. This will be the main task that provides data data needed for the safety checker to detect if the player has been teleported to a different coordinate. This task must only run in the overworld and not spawn.

Safety measures to be implemented if possible:
1. The mentioned 10 blocks offset from the player's current position. Offset value must be configurable via modmenu.
2. If possible, read the current player list in the server. If several configured user exists in the server, stop anti-afk process and notify the user via in-game chat message and telegram. Allow adding to avoid users in the config and via modmenu.
3. If possible, detect nearby players and if they are of the configured user, stop anti-afk process and notify the user via in-game chat message and telegram.
